## Открыть и запустить

Для локального предпросмотра запустите `Start-Local.ps1` или выполните команды ниже.

- Сайт: <http://127.0.0.1:4321/ru/>
- English: <http://127.0.0.1:4321/en/>

Корень проекта:

```powershell
Set-Location 'D:\Библиотека\Исследования\Искусственный интеллект\приложения\RuslanNazarovSite\repository'
npm ci
npm run build
npm run preview -- --port 4321
```

Для запуска предпросмотра в фоне: `.\Start-Local.ps1`.
Нужен Node.js 24. Зависимости фиксирует `package-lock.json`.
Для разработки с автоматическим обновлением: `npm run dev`.
Полный поиск Pagefind проверяйте в **собранном preview**, а не в dev.
Готовая статическая сборка находится в `dist/`.

ТЗ оставлено нетронутым в родительской папке. Клон сделан в `repository/`,
чтобы не перезаписывать файл ТЗ и сохранить существующую Git-историю.

## Управление содержимым через Codex

Задачи по изменению сайта передаются в чат. Материалы хранятся в `src/content/`, настройки и публичные редакции — в `src/data/`, изображения и файлы — в `public/`.

Перед изменением опубликованного текста сохраняется полная двуязычная редакция командой `npm run content:release`. Для публикации нужны `publish: true`, `ready_ru: true`, `ready_en: true` и непустые заголовки и аннотации. Для `editorialStatus: final` требуется полный текст на двух языках. Пока новая редакция не готова, сайт использует прежнюю полную версию из `src/data/published.json`.

После правок выполняются проверки и сборка. Отправка изменений в `main` запускает публикацию через GitHub Actions.

## Граф и импорт парсера

Актуальный Python-репозиторий не предоставлен. Поэтому:

- `src/data/graph/source.json` — пока пустой реальный источник.
- `src/data/graph/demo.json` — отдельная демонстрация интерфейса по
  снимку перечня узлов от 29.09.2026; не live sync и не одобренные результаты.
- В демонстрации явно указана необходимость сверки типов, статусов и описаний.
- Настоящие разрешения находятся в `src/content/graph-overrides/{publicId}.json`.

Для нормализованного экспорта:

```powershell
npm run graph:import -- 'C:\path\to\export.json'
npm run validate
npm test
```

Если доступен доверенный `graph_data.py`, пример адаптера:

```powershell
python scripts/export-parser-graph.py --module 'C:\path\to\graph_data.py' --output '.local/parser-export.json'
npm run graph:import -- '.local/parser-export.json'
```

Адаптер выполняет явно указанный локальный Python-модуль. Сначала проверьте
его код и согласуйте отображение полей с текущей схемой парсера.
Для него нужен Python 3; сам сайт Python не требует. В текущей среде адаптер
проверен встроенным Python Codex, поскольку системная команда `python`
указывает на неработающий Windows App Alias. Для теста с конкретным
интерпретатором задайте `EXPORT_TEST_PYTHON` равным пути к `python.exe`.
Отсутствующие переводы и неизвестные типы/статусы останавливают экспорт;
адаптер их не придумывает. Карта `originalKey → publicId` сохраняет ID между экспортами.

Импорт не меняет существующие аннотации и разрешения. Для новых ID всегда
создаётся `approvedForPublication: false`. Добавления, изменения, удаления и
осиротевшие overrides отражаются в `.local/graph-import-report.json`.
Удаление узлов, конфликты ID, циклы и некорректные рёбра требуют исправления
до замены рабочего источника. Никаких автоматически придуманных обходных рёбер.

Владелец отдельно включает `approvedForPublication` в данных графа. Любой из трёх
исследовательских статусов может быть публичным. «Подтверждено» означает
подтверждение в авторской модели, а не научную рецензию.
Аннотации сайта не меняют математические типы, рёбра, предшественников и статусы исходного Python-графа.

## Проверки

```powershell
npm run check
npm test
npm run build
npx playwright install chromium
# Предпросмотр сайта должен быть запущен на 4321:
npm run test:browser
# Изолированная копия для непредоставленных материалов и отключённых сервисов:
npm run test:features
```

`check` проверяет Astro/TypeScript. Unit-тесты проверяют публикационные барьеры,
RU/EN fallback, безопасный Markdown/LaTeX, структуру данных и повторный импорт графа.
Сборка проверяет ссылки, языки, RSS, Pagefind, исключение черновиков и байты Яндекса.
Playwright проверяет темы, языки, мобильные страницы, фильтры, граф и поиск.
Feature fixtures используют отдельный каталог `.local/features/` и имитацию
Formspree/Cloudflare: настоящие сообщения не отправляются, данные владельца
не заменяются. Проверяются также итоговые главы, тематические ленты и скрытые узлы.
Скриншоты и журналы остаются в игнорируемой папке `.local/`.

## Публикация

Сайт опубликован с разрешения владельца 20.10.2026. GitHub Pages использует
GitHub Actions. Отправка в main запускает проверки, сборку и развёртывание;
отправка в рабочую ветку запускает только проверки.

Обычная работа: передать задачу Codex → проверить изменения и предпросмотр → опубликовать через GitHub Pages.
Ход выполнения: <https://github.com/Ruslan-Nazarov/Ruslan-Nazarov.github.io/actions/workflows/deploy.yml>.

Ручной повторный запуск доступен в Actions → Publish approved site to GitHub Pages →
Run workflow, ветка main, подтверждение PUBLISH. Используется сохранённая
авторизация Git.

Подробные решения и ограничения: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).
