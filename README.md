# Персональный сайт Руслана Назарова

Статический сайт на GitHub Pages в стиле «академический журнал и живая лаборатория»: тёплая бумага, графитовый текст, янтарно-терракотовые акценты и знак R · N. Светлая и тёмная палитры следуют системной настройке. Шрифты Inter и Source Serif 4 хранятся локально вместе с открытыми лицензиями в `public/fonts/`; логотипы, иконки и превью для соцсетей — в `public/icons/`.

## Разделы

- Об авторе — биография и фотография.
- Контакты — электронная почта и публичные профили.
- Тезисы по диалектике — единый полный текст со всеми разделами: введением, диалектикой, математикой, физикой, образованием и искусственным интеллектом.
- Тезисы об ИИ — часть «Тезисов по диалектике», выделенная на отдельную страницу: только текст в кавычках из пункта 12 раздела об ИИ. Текст берётся из общего источника тезисов.
- Статьи — только уже перенесённые полные тексты.
- Блог — авторские посты с датой, категорией и хештегами. Каждый пост доступен на языке оригинала; русская и английская ленты показывают свои записи.
- Книги — обложки, описания и ссылки на книжные сайты.
- Проекты — два подраздела: ИИ (DialecticAI, диалектические конспекты и алгоритм ИИ) и Вайбкодинг. Приложения вайбкодинга собраны по категориям; в начале — ссылка на промпты и задания. Страницы приложений описывают назначение, возможности и доступ.

Есть русская и английская версии. Тексты и существующие адреса сохранены. Старые статьи со ссылками на Medium доступны по прежним адресам, но не включены в новый раздел полных статей. Поиск доступен в шапке и внизу страницы. На главной показаны четыре избранные полные статьи (поле `featured`); весь список остаётся в разделе «Статьи». Короткие аннотации общие для главной, каталога и страницы материала.

Октябрьская редакция тезисов доступна целиком и по главам на обоих языках, а также в PDF на русском и английском с кликабельным оглавлением. PDF подготовлены в режиме выпуска, без пометки черновика. Английский текст дополнительно доступен в Word и Markdown. Незавершённое предисловие исключено.

## Публикация

К открытию 11 ноября 2026 года в `src/data/launch.json` установлено `enabled: false`. GitHub Pages использует `npm run build:public`, который при этой настройке собирает полный сайт. Для появления изменений на публичном сайте их нужно опубликовать. Для локальной работы используйте `npm run dev` или `npm run build`.

Публикация текущей версии разрешена автором 1 ноября 2026 года. Рабочая ветка — `feat/research-website`; отправка проверенной версии в `main` запускает развёртывание GitHub Pages. Правки исследовательских текстов вносим по указанию автора.

Незаполненные места для иллюстраций не показываются посетителям. Их привязки остаются в `src/data/media.json`: когда появятся реальные изображения, их можно подключить без изменения текстов. Дополнительные иллюстрации и перенос оставшихся статей с Medium не мешают выпуску текущего состава материалов.

[Места для авторской вычитки](docs/REVIEW-2026-10-31.md) · [Конкретный перечень иллюстраций](docs/ILLUSTRATIONS-2026-10-31.md).

PDF собираются командой `npm run theses:pdf` из текущего текста глав. Нужен Python с `reportlab`, `pypdf`, `pdfplumber` и шрифты Times New Roman. Путь к Python можно задать через `PDF_PYTHON`, каталог шрифтов — через `PDF_FONT_DIR`. Результаты сохраняются в `output/pdf/` и копируются в `public/theses/october-2026/`. Экспорт проверяет наличие всех абзацев и их порядок. После правок текста необходимо пересоздать PDF; перед публичным выпуском использовать `npm run theses:pdf -- --release` для удаления пометки черновика с титула.

Перед публикацией: `npm run check`, `npm test`, `npm run build`, затем браузерная проверка чтения, меню, языков и поиска. После авторской вычитки изменения можно перенести в `main`, где автоматически запускается публикация.

После подключения YouTube Analytics его редактор блога добавляет одну запись в `src/content/blog/` в ветке `main`. Сайт включает её в очередную сборку GitHub Pages. Черновики и расшифровки хранятся в YouTube Analytics.

## Работа с материалами

Материалы добавляем через Codex по выбору автора. При переносе статей сохраняем текст без изменений: адаптируем только оформление, изображения, формулы и вёрстку. Новые переводы и изменения содержания согласуются отдельно.

Тексты: `src/content/`. Общие сведения: `src/data/site.json`. Меню: `src/lib/navigation.mjs`. Основное оформление: `src/styles/simple.css`. Обложки: `public/images/books/` — оригинальные `logo.png` из публичных репозиториев `handbook_ai` и `handbook_Languages`, без изменений.

Для проектов ссылка на GitHub выводится только при наличии в данных. Отсутствие репозитория не мешает странице с описанием.

## Запуск

Требуется Node.js 24.

```powershell
npm ci
npm run dev
```

Русская версия: http://127.0.0.1:4321/ru/

Для авторской вычитки готовой сборки можно запустить `./Start-Local.ps1` из PowerShell: скрипт пересоберёт сайт и запустит локальный предпросмотр по тому же адресу. После перезагрузки компьютера запустите его снова.

```powershell
npm run check
npm test
npm run build
npm run preview -- --port 4321
npm run test:browser
```

`npm run build` создаёт статические файлы в `dist/` и проверяет внутренние ссылки. Существующий GitHub Actions публикует сайт при отправке в `main`. Локальные изменения сами по себе не публикуются.

## Поиск и аналитика

Карта сайта создаётся при сборке; её адрес указан в `public/robots.txt`. После публикации добавьте сайт в Google Search Console и Яндекс Вебмастер, подтвердите права и отправьте `https://ruslan-nazarov.github.io/sitemap-index.xml`. В кабинетах можно проверить обработку карты и состояние страниц; отправка карты не гарантирует индексацию.

Для Яндекс Метрики создайте счётчик для `https://ruslan-nazarov.github.io/` и укажите его числовой номер строкой в `yandexMetricaId` в `src/data/site.json`. При пустом значении счётчик не загружается; в локальном предпросмотре редактора он также отключён. В настройках счётчика оставьте Вебвизор, анализ форм и передачу контактных данных отключёнными. После публикации проверьте поступление данных в Метрике. При необходимости создайте цели типа «JavaScript-событие» с идентификаторами `file_click` (нажатие на ссылку файла), `external_link_click` (переход на внешний сайт) и `contact_click` (ссылка электронной почты или телефона). Цели необходимо создать в кабинете, один клик может соответствовать нескольким целям. Переходы к страницам книг и проектов видны в отчётах по страницам. На корневом адресе выполняется переход на языковую версию с сохранением параметров ссылки; счётчик загружается на языковых страницах.
