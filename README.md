# Ruslan-Nazarov.github.io

Редактор обновлён 24.10.2026. Слева — страницы и статьи, включая черновики.
На странице редактируются заголовок, краткое описание, текст и ссылки на материалы.
«+ Страница» создаёт самостоятельную страницу, «+ Статья» — текст на сайте,
«+ Ссылка» — публикацию на стороннем ресурсе. Адрес получается из названия автоматически.
Статьи выбираются по названиям. Из списка раздела их можно убрать или вернуть;
новые статьи появляются в своём разделе автоматически. Служебные экраны,
подписи кнопок и расположение элементов не входят в редактор содержимого.

Переключатель Русский / English / Оба языка сохраняет введённые правки.
Изображения, дополнительные тексты и параметры публикации свёрнуты.
Готовую новую страницу можно добавить в меню одним флагом.
«Сохранить» записывает локальные правки, «Обновить предпросмотр» пересобирает сайт.
Проверка полного сценария: `npm run test:editor`.

Актуальный аудит: [docs/AUDIT-2026-10-21.md](docs/AUDIT-2026-10-21.md).
В отчёте — исправления, проверки, состояние ссылок и список материалов
для дальнейшего наполнения. Изменения аудита подготовлены локально.

Локальная реализация **Ruslan Nazarov | AI Researcher** по ТЗ от 20.10.2026.
Исходная история репозитория и файл Яндекс Вебмастера сохранены. Работа ведётся в
`feat/research-website`. С разрешения владельца сайт опубликован:
<https://ruslan-nazarov.github.io/>.

## Открыть и запустить

Дважды нажмите `Запустить редактор.bat` в родительской рабочей папке
или `Start-Editor.bat` в этом репозитории. Батник запускает сайт и редактор
в фоне и открывает редактор в браузере. При первом запуске устанавливает зависимости.

После запуска доступны:

- Сайт: <http://127.0.0.1:4321/ru/>
- English: <http://127.0.0.1:4321/en/>
- Граф: <http://127.0.0.1:4321/ru/projects/mathematical-parser/graph/>
- Локальный редактор: <http://127.0.0.1:4322/>

Корень проекта:

```powershell
Set-Location 'D:\Библиотека\Исследования\Искусственный интеллект\приложения\RuslanNazarovSite\repository'
npm ci
npm run build
npm run preview -- --port 4321
```

В другом терминале, из той же папки:

```powershell
npm run editor
```

Для запуска обоих серверов в фоне: `.\Start-Local.ps1`.
Нужен Node.js 24. Зависимости фиксирует `package-lock.json`.
Для разработки с автоматическим обновлением: `npm run dev`.
Полный поиск Pagefind проверяйте в **собранном preview**, а не в dev.
Готовая статическая сборка находится в `dist/`.

ТЗ оставлено нетронутым в родительской папке. Клон сделан в `repository/`,
чтобы не перезаписывать файл ТЗ и сохранить существующую Git-историю.

## Локальное редактирование

Интерфейс редактора переработан 22.10.2026: поиск материалов, адаптивные формы,
закреплённые действия медиабиблиотеки и защита несохранённых правок.
Акценты приложения — оранжевые: `#f2994a`, наведение `#d87d2d`, текст акцента
`#9c4c16`. Эта палитра общая для сайта, редактора, медиабиблиотеки и фоторедактора.
Материал и поле для вставки теперь можно выбрать прямо в медиабиблиотеке.
После обновления файлов достаточно перезагрузить вкладку редактора.
Основной текст открывается в визуальном редакторе: шрифт 17 px, заголовки,
жирный и курсив, списки, цитаты, ссылки, формулы и вставка из медиабиблиотеки.
Есть отмена/повтор, разворачивание на весь экран и сохранение по Ctrl+S.
Вкладка **Markdown** открывает исходник. Таблицы, код и сложные блоки
сохраняются без изменений; их содержимое редактируется в исходнике.
Переключение режимов без правок не изменяет текст. Проверка: `npm run test:rich-text`.
Проверка интерфейса: `npm run test:editor`.
Подробности: [отчёт о переработке и проверках](docs/EDITOR-UI-2026-10-22.md).

Выбор **«ИИ / Я написал»** относится к крупным текстовым блокам и виден только владельцу в локальном редакторе. Отметки независимы для RU и EN и сохраняются в `_authorship` рядом с полями. Если авторство не указано, автоматически выбирается «ИИ»; явная отметка «Я написал» сохраняется. На публичном сайте метки и пояснения авторства не выводятся.

Кнопка **«Загрузить изображение»** сразу открывает выбор файла. Затем нажмите
**«Загрузить и сохранить локально»**. Alt RU/EN можно заполнить позже;
они обязательны перед вставкой в материал или привязкой к заглушке.
Сохранённые сведения об авторстве подписей и alt остаются в данных без значков.

**«Обрезать / изменить фото»** работает с PNG, JPEG и обычным WebP как до
загрузки, так и для файлов в библиотеке. Выделите область мышью/пальцем или
задайте проценты; доступны пропорции, поворот, отражение, яркость и контраст.
Можно сохранить копию или заменить файл с сохранением его URL. При первой
замене исходник сохраняется в `.local/media-originals/`; кнопка
**«Восстановить исходник»** возвращает его точные байты. Эта резервная копия
остаётся локальной. GIF, SVG и анимированный WebP не изменяются этим редактором.

**«ИИ · заполнить поля»** предлагает название, теги, alt и подписи RU/EN;
маленькие кнопки **«ИИ»** заполняют одно выбранное поле. Можно указать контекст
фото, исправить результат или нажать **«Отменить заполнение ИИ»**. Заполненные
тексты получают отметку «ИИ» и сохраняются обычной кнопкой метаданных/загрузки.
Изображение отправляется в OpenAI только по нажатию кнопки. Для анализа
используется уменьшенная копия без EXIF; запрос выполняется с `store: false`.

Подключение ИИ находится на локальном сервере: `OPENAI_API_KEY` из окружения
или `.env`. Можно использовать уже существующий файл другого проекта через
игнорируемый `.local/media-ai.json`: `{"credentialFile":"путь/к/.env","model":"gpt-5-mini"}`.
Ключ читается из указанного файла, в браузер не передаётся. Параметр
`MEDIA_AI_MODEL` переопределяет модель, `MEDIA_AI_DISABLED=1` отключает ИИ
для изолированных тестов. Сценарий интерфейса: `npm run test:photo`.

У каждого русского текстового поля с английской парой есть **«Перевести на
английский»**. Кнопка отправляет только выбранный русский текст подключённому
провайдеру перевода и заполняет соответствующее поле English. Формулы, код,
Markdown-разметка и адреса ссылок сохраняются. Есть отмена замены; результат
остаётся несохранённой правкой, которую можно проверить и сохранить обычной кнопкой.

Перевод переключён на **GigaChat-3-Ultra** в Freemium для физлиц.
Игнорируемый `.local/translation-ai.json` задаёт `provider: "gigachat"`,
`model: "GigaChat-3-Ultra"`, `scope: "GIGACHAT_API_PERS"` и `credentialFile`
с путём к существующему `.env`. Ключ `GIGACHAT_AUTH_KEY` или
`GIGACHAT_CREDENTIALS` читается только сервером. Относительный
`GIGACHAT_CA_BUNDLE` разрешается от папки этого `.env`; проверка TLS включена.
Автоматического перехода на OpenAI или платные модели нет. Настройки анализа
изображений задаются отдельно в `.local/media-ai.json`.

Редактор отмечает изменения RU/EN и подсвечивает пару, если тексты менялись
после последнего согласования. **«Сравнить RU/EN»** открывает обе версии рядом
с датами правок; **«Подтвердить соответствие»** фиксирует ручную проверку.
После автоматического перевода метка обновляется автоматически. Сравнение и
отслеживание полностью локальные: в `.local/editor-language-state.json` хранятся
только отпечатки версий и даты. Метки сохраняются после перезапуска и не входят
в публичную сборку. Старые тексты изначально отмечены как ещё не проверенные.
Проверка интерфейса: `npm run test:translation`.

направления исследований, обе книги, обзор тезисов и содержание пяти глав,
две реальные новости о публикации страниц сайта. Обзоры глав явно отделены
от ещё готовящегося окончательного текста. Их можно читать по отдельности
и одной страницей. Контактный email взят из публичного README языкового
приложения. Источники и оставшиеся материалы: `docs/SECTION-COMPLETION.md`.

1. Откройте <http://127.0.0.1:4322/>. Слева находятся страницы, статьи и записи.
   Выберите название, чтобы править заголовок, краткое описание, текст и ссылки.
2. Кнопки **«Страница»**, **«Статья»**, **«Ссылка»** создают новый материал.
   Адрес формируется из названия. Материалы выбираются по названиям.
3. Пишите в визуальном редакторе. Переключатель RU / EN / RU + EN меняет
   язык редактирования. Изображения и PDF находятся в **«Изображения и вложения»**.
4. Нажмите **«Сохранить»**, затем **«Обновить предпросмотр»**.
   Локальный предпросмотр включает черновики и поиск; он строится отдельно
   в `.local/editor-preview` и не меняет публичную сборку.
5. Когда оба языка готовы, выберите **«Готов к публикации»**, сохраните
   и нажмите **«Опубликовать на сайте»**. Для незавершённой правки уже выпущенного
   материала используйте **«Новая редакция — ещё не готова»**.
6. Откройте **«Медиабиблиотека»**. Загрузите изображение, задайте
   название, проект, теги, alt и подписи RU/EN. Каталог объединяет
   `public/images/` и `public/media/`: доступны поиск по всем метаданным,
   фильтры проекта/тега, сортировка и полный размер.
7. На вкладке **«Заглушки / задачи»** выберите файл для нужного ID и нажмите
   **«Сохранить привязку»**. Семь мест papanda уже имеют авторские alt и подписи
   RU/EN; их можно редактировать отдельно от общих метаданных изображения.
   До назначения файла сайт показывает заглушку. После назначения пересоберите
   сайт и проверьте `/ru/projects/papanda/` и `/en/projects/papanda/`.
8. В полях обложки, портрета и галереи есть **«Выбрать из медиабиблиотеки»**;
   у больших текстов — **«Вставить изображение»**. Повторная загрузка не нужна.
   Через верхнюю кнопку **«Медиабиблиотека»** тоже можно вставлять:
   выберите **«Материал»**, затем поле в **«Куда добавить изображение»**, выберите фото и нажмите
   **«Вставить в материал»**. Изменённые alt и подписи сохраняются при вставке;
   затем сохраните сам материал кнопкой **«Сохранить»**.
   В тексте хранится `[[media:постоянный-id]]`; сайт подставляет изображение,
   alt и подпись текущего языка. PDF загружается прежней кнопкой вверху;
   возвращённый путь используется в `pdf_ru/en`.

В карточке файла можно менять метаданные и заменить изображение того же
формата, сохранив ID и URL во всех материалах. Новые изображения хранятся
в `public/media/<project>/`; реестр — `src/data/media.json`, оба сохраняются
в Git. Лимиты: 8 MiB и 40 млн пикселей. Расширение, MIME и фактическое
содержимое проверяются. SVG допускает только безопасный статический набор
элементов; активное содержимое, внешние ресурсы, CSS и ссылки запрещены.
Скриншоты с формулами и мелким текстом сохраняются без автоматического пережатия.

Перед удалением показаны места использования и запрашивается подтверждение.
Прямая ссылка из материала, настроек, кода или `published.json` блокирует
удаление: сначала уберите ссылку. Изображение, привязанное только к заглушкам,
можно удалить с подтверждением — эти места снова станут заглушками. Отмена
сохраняет файл и привязки. Используйте обезличенные снимки.

Pages CMS выбирает файлы **репозитория**, а не локальной папки. В `.pages.yml`
добавлен источник `/media` для его выбора изображений. Локальные поиск,
метаданные, задачи и безопасное удаление обеспечивает именно этот редактор.

Редактор слушает только loopback, не является backend публичного сайта
и не попадает в `dist`. Записи сохраняются только в этом checkout.
Кнопка **«Опубликовать на сайте»** проверяет и собирает материалы, создаёт
локальный коммит и после отдельного подтверждения отправляет его в main репозитория персонального сайта.
GitHub Actions автоматически обновляет сайт после успешных проверок (обычно 1–2 минуты).
Ссылка на результат публикации появляется в редакторе. Сначала сохраните правки.
Кнопки **«Сохранить»** и **«Обновить предпросмотр»** работают локально.

Автоматически добавляются в коммит только материалы, настройки и загруженные
изображения/PDF. Изменения кода, переименования, конфликты и новые удалённые
коммиты останавливают публикацию с сообщением; принудительная перезапись не используется.
Для отправки нужен Git и действующая авторизация GitHub в Git Credential Manager.
Репозитории книг и файл подтверждения Яндекса не входят в список редактируемых файлов.

## Pages CMS через GitHub

Конфигурация `.pages.yml` опубликована в GitHub. Pages CMS читает файлы
непосредственно из репозитория. Для подключения:

1. Войдите на <https://app.pagescms.org/> через стандартную авторизацию GitHub.
2. Разрешите GitHub App доступ к **этому** репозиторию, без доступа к книгам.
3. Выберите `Ruslan-Nazarov/Ruslan-Nazarov.github.io` и ветку `main`. Сохранение в `main` запускает обновление сайта.
4. Используйте те же коллекции, что в локальном редакторе.
5. Перед незавершённой правкой ранее опубликованного материала запустите
   действие **«Сохранить полные RU+EN версии перед новой редакцией»**.
   Оно фиксирует `src/data/published.json` в выбранной ветке. Оно не деплоит сайт.
   Если у GitHub App нет права запускать Actions, выполните это действие
   в GitHub → Actions → Save complete bilingual revisions либо локально
   `npm run content:release` и сохраните snapshot в ветке.

Правило публикации: нужны одновременно `publish: true`, `ready_ru: true`,
`ready_en: true` и непустые заголовки/аннотации. Для `editorialStatus: final`
обязателен полный текст на двух языках. Пока перевод новой редакции не готов,
выберите «Новая редакция — ещё не готова» — сайт использует прежнюю полную версию из snapshot.
`publish: false` означает намеренное снятие материала с сайта.
Локальный редактор автоматически сохраняет предыдущую полную версию перед правкой.

Черновики могут быть видимы в исходном публичном GitHub, но не в HTML,
клиентском JSON, поиске, RSS и sitemap. Не храните секреты в исходниках
и загруженных в `public/` медиа: эта папка предназначена для публичных файлов.

## Граф и импорт парсера

Актуальный Python-репозиторий не предоставлен. Поэтому:

- `src/data/graph/source.json` — пока пустой реальный источник.
- `src/data/graph/demo.json` — отдельная демонстрация интерфейса по
  снимку перечня узлов от 29.09.2026; не live sync и не одобренные результаты.
- В демонстрации явно указана необходимость сверки типов, статусов и описаний.
- Настоящие разрешения находятся в `src/content/graph-overrides/{publicId}.json`.

Для нормализованного экспорта:

```powershell
npm run graph:import -- 'C:\path\to\export.json'
npm run validate
npm test
```

Если доступен доверенный `graph_data.py`, пример адаптера:

```powershell
python scripts/export-parser-graph.py --module 'C:\path\to\graph_data.py' --output '.local/parser-export.json'
npm run graph:import -- '.local/parser-export.json'
```

Адаптер выполняет явно указанный локальный Python-модуль. Сначала проверьте
его код и согласуйте отображение полей с текущей схемой парсера.
Для него нужен Python 3; сам сайт Python не требует. В текущей среде адаптер
проверен встроенным Python Codex, поскольку системная команда `python`
указывает на неработающий Windows App Alias. Для теста с конкретным
интерпретатором задайте `EXPORT_TEST_PYTHON` равным пути к `python.exe`.
Отсутствующие переводы и неизвестные типы/статусы останавливают экспорт;
адаптер их не придумывает. Карта `originalKey → publicId` сохраняет ID между экспортами.

Импорт не меняет существующие CMS-аннотации и разрешения. Для новых ID всегда
создаётся `approvedForPublication: false`. Добавления, изменения, удаления и
осиротевшие overrides отражаются в `.local/graph-import-report.json`.
Удаление узлов, конфликты ID, циклы и некорректные рёбра требуют исправления
до замены рабочего источника. Никаких автоматически придуманных обходных рёбер.

Владелец отдельно включает `approvedForPublication` в CMS. Любой из трёх
исследовательских статусов может быть публичным. «Подтверждено» означает
подтверждение в авторской модели, а не научную рецензию.
CMS не редактирует математические типы, рёбра, предшественников и статусы исходного Python-графа.

## Проверки

```powershell
npm run check
npm test
npm run build
npx playwright install chromium
# Сайт и редактор должны быть запущены на 4321 и 4322:
npm run test:browser
# Изолированная копия для непредоставленных материалов и отключённых сервисов:
npm run test:features
# Изменение всех публичных материалов и проверка всех 88 HTML-адресов в отдельной копии:
npm run test:editor-pages
# Изолированный сценарий медиабиблиотеки, без обращений к GitHub:
npm run test:media
```

`check` проверяет Astro/TypeScript. Unit-тесты проверяют публикационные барьеры,
RU/EN fallback, безопасный Markdown/LaTeX, CMS и повторный импорт графа.
Сборка проверяет ссылки, языки, RSS, Pagefind, исключение черновиков и байты Яндекса.
Playwright проверяет темы, языки, мобильные страницы, фильтры, граф, поиск и редактор.
Feature fixtures используют отдельный каталог `.local/features/` и имитацию
Formspree/Cloudflare: настоящие сообщения не отправляются, данные владельца
не заменяются. Проверяются также итоговые главы, тематические ленты и скрытые узлы.
Скриншоты и журналы остаются в игнорируемой папке `.local/`.

## Публикация

Сайт опубликован с разрешения владельца 20.10.2026. GitHub Pages использует
GitHub Actions. Отправка в main запускает проверки, сборку и развёртывание;
отправка в рабочую ветку запускает только проверки.

Обычная работа: запустить батник → изменить и сохранить материал →
пересобрать и проверить предпросмотр → нажать «Опубликовать на сайте».
Ход выполнения: <https://github.com/Ruslan-Nazarov/Ruslan-Nazarov.github.io/actions/workflows/deploy.yml>.

Ручной повторный запуск доступен в Actions → Publish approved site to GitHub Pages →
Run workflow, ветка main, подтверждение PUBLISH. Используется сохранённая
авторизация Git; GitHub CLI не требуется для кнопки локального редактора.

Подробные решения и ограничения: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).
